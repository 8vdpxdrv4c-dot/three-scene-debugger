00为什么需要它

Vibe coding 3D 场景时，最贵的不是写代码，是验证。

画面是唯一反馈，但它不可读

灯光强度、roughness、bloom 阈值、相机位置、贴图 repeat 全是标量。代码里写 1.2 还是 1.5，只能靠猜。

一轮对话只能验证一个猜测

改一行 → 保存 → 等 HMR → 看画面 → 截图 → 描述给 Agent。一次迭代几十秒，猜中一个参数往往要好几轮。

描述损耗

「再亮一点点」「那面墙有点脏」变不成数值；Agent 拿不到 name / uuid，只能在 scene.traverse 里乱找。

token 花在往返上

每一轮都要把场景状态、报错、截图重新讲一遍，真正用于「改」的部分少得可怜。

把「猜」换成「点」

原来现在
改代码试参数，等构建看结果拖滑块实时看画面，松手才记一条改动
用文字描述「哪个物体」点选即定位，拿到准确的 name / uuid / 材质槽位
改坏了推倒重来逐条撤销 + 冲突检测，试错成本接近零
多轮口述场景状态给 Agent一次 aiPrompt() 复制完整参数 + 定位代码块
让 Agent 猜数值导出 target.position.y = 2.45 这种可直接执行的代码
省下的是两样东西：时间——一轮迭代从「几十秒」压到「一次拖动」；token——把多轮往返描述压成一次复制。

01它能做什么

一句话：不改架构，给已经跑起来的场景加一个 inspector。

场景树 SceneTree

完整层级 traverse，name / 类型 / uuid、折叠、搜索、类型过滤。点一行 = 选中对象 + 相机缓动飞过去取景。

属性检查 Inspector

变换、可见性、阴影标志、userData；材质 / 纹理 / 灯光 / 相机 / 场景 / renderer 按类型给不同控件。

实时调参 UI

滑块探索、数字框精确输入；字段名按住左右拖动改值（Shift ×10、Alt ×0.1），整段拖动只记一条改动。

材质切换 Material

Standard / Physical / Phong / Lambert / Basic / Toon / Normal / Matcap / Depth / Shadow，材质数组按槽位，可同步共用材质的对象。

程序化贴图库 Texture

12 套材质在浏览器里用周期噪声现算基础色 + 法线 + 粗糙度，零图片、零请求、四边无缝。

HDR 素材库 Assets

4 个 CC0 HDR 天空盒 + 1 个 LDR 环境 + 8 套 PBR 贴图，清单驱动、懒加载；删掉目录照样能用程序化环境。

后期处理 PostFX

Bloom / 调色 / 暗角 / 色差 / 颗粒 / 锐化 / 描边 / 像素化，外加线框、法线、剪影视图。已有 EffectComposer 就接管它的 Bloom，没有才插自己的 pass。

景深 Bokeh

独立 BokehPass 通道，默认关闭、按当前机位自动算 focus/aperture，关闭时整条 pass 摘除并释放中间目标。

场景编辑 Editor

点选高亮、TransformControls 拖拽、加光源、克隆、删除、聚焦、网格与坐标轴、光源 helper、截图与统计。

性能 Perf

来自你 tick 的真实渲染 FPS、draw call、三角形数，以及纹理与几何内存估算——估算就说是估算，不冒充显存读数。

改动追踪 Undo

每条改动深拷贝 old/new，逐条撤销并做冲突检测，不会用旧值覆盖后来的新值。

导出 Export

精简快照 JSON、一个对象一段可执行代码、后期动作导出成 tsd.setPostFX(...)，或一键复制修改提示词。

02面板与入口

页面左上角常驻一个红色按钮，面板默认关闭，用完就走。

  • 点按钮开关面板，只有面板打开时才允许点选与拖拽，关闭会同时清空选中。
  • 入口按钮可以拖走（双击复位到左上角），面板拖标题栏也能换位置；按钮、面板位置和面板宽度都会记住，换屏后自动夹回视口内。
  • 标题下方「展开全部 / 收起全部 / 复位布局」，分组是带箭头的卡片。
  • 快捷键：W / E / R 换手柄、Esc 取消选中、Ctrl / Cmd + Z 撤销最近一条改动。
  • 面板底部常驻「复制修改提示词」大按钮，显示改动处数，无改动时禁用。

03怎么接进页面

装了 Agent Skill 之后不用自己找接入点——说一句话就行；要手写也有三种方式。

说一句话就能接入

给我启动 3D 场景调试 启用 3D 场景调试 3D 场景调试大师 接入 three-scene-debugger 我要调后期 关闭 3D 场景调试

这些说法都等于「把调试器接到当前项目」。Agent 的执行顺序是固定的： 探测构建工具与 three 版本 → 定位 scene / camera / renderer → 选 ESM 或 UMD → 插入 DEV 分支 → 验证面板能开 → 回报改了哪个文件、怎么关。

已接入且能跑的项目不会重复插入，只补缺失项；找不到 scene 就停下给候选位置，不翻闭包、不猜 React 私有数据，也不为接入改构建配置。说「关闭 / 卸载」默认移除接入代码，说「检查接好没」则只读检查。

A · ESM + 构建期 DEV 分支（推荐）

terminal
# GitHub
npm install -D github:8vdpxdrv4c-dot/three-scene-debugger

# 本地副本 / 内网
npm install -D /absolute/path/to/three-scene-debugger
main.js
let sceneDebug;
if (import.meta.env.DEV) {
  const { createSceneDebugger } = await import('three-scene-debugger/dist/three-scene-debugger.mjs');
  sceneDebug = createSceneDebugger({ scene, camera, renderer, THREE, controls });
}
// 在已有渲染帧末尾可选加一行，绝不新增第二个 render 循环
// sceneDebug?.tick(now);
// 卸载 / HMR：sceneDebug?.destroy(); sceneDebug = undefined;

B · 直接引用预生成单文件

app.js
import { createSceneDebugger } from './three-scene-debugger/dist/three-scene-debugger.mjs';

const sceneDebug = createSceneDebugger({ scene, camera, renderer, THREE });

C · UMD / 没有构建器的单页 HTML

index.html
<script src="./three-scene-debugger/dist/three-scene-debugger.js"></script>
<script>
  const sceneDebug = ThreeSceneDebugger.createSceneDebugger({ scene, camera, renderer, THREE });
</script>
ESM 与 UMD 是两种格式，不能把 UMD 改个扩展名当 ESM 用。需要重新生成时跑 node scripts/build.cjs，它从同一份核心产出 dist/*.mjs 与 UMD 副本。

参数怎么传

createSceneDebugger(options)
sceneDebug = createSceneDebugger({
  scene, camera, renderer, THREE,          // 必填：显式引用，THREE 用页面同一份
  controls,                                 // 可选：OrbitControls
  transformControls: TransformControls,     // 可选：不传则只有选中高亮，没有拖拽手柄
  lightHelpers: true,                       // 默认 true，为每个光源挂 helper
  assets: './assets/',                     // 可选：HDR 天空盒 + PBR 贴图
  autoNear: true,                          // 可选：聚焦极小物体时临时压低 near
  postfx: { enabled: false },             // 可选：覆盖后期默认值
  bokehPass: BokehPass,                     // 可选：景深通道需宿主注入构造函数
  onSelect: obj => {}, onToggle: open => {},
});
为什么 addon 要注入？ 技能内部不 import three/examples/jsm，否则会打进第二份 three，两套 WebGLRenderTarget 和常量互不认账。所以 TransformControls、BokehPass 由宿主传构造函数，THREE 也必须是同一份 namespace。

04常用操作

面板能做的，API 都能做；反之亦然。

api.js
// 选中与取景
sceneDebug.selectObject(mesh);
sceneDebug.focusObject(mesh.uuid, { instant: false, duration: 600 });
sceneDebug.setTransformMode('rotate');        // 画布上也支持 W / E / R
sceneDebug.addLight('directional', { intensity: 2 });
sceneDebug.screenshot();

// 属性与撤销
sceneDebug.set(mesh, 'position.x', 2);
sceneDebug.undo(record.id);

// 后期（线性 HDR：1.0 = 白点以上）
sceneDebug.setPostFX('bloom.threshold', 1.05);
sceneDebug.setPostFX('bloom.enabled', false);
sceneDebug.composerInfo();                    // {mode:'attach'|'inject'|'off', ...}
sceneDebug.focusBokeh();                      // 对焦到观察中心 / 选中物体

// 环境与材质
sceneDebug.setEnvironment('hdr:venice_sunset');
sceneDebug.setMaterial(mesh.uuid, 'MeshPhysicalMaterial', { slot: 0, spread: true });
sceneDebug.applyTexturePreset(mesh.uuid, 'oak', {
  slots: ['map', 'normalMap', 'roughnessMap'], size: 512, repeat: 4
});
场景状态后期页签做什么关掉「接管」会怎样
有 EffectComposer + Bloom pass 接管：strength/radius/threshold 直连该 pass，调色/暗角另插一条 pass 在编码之前 完全交还宿主，Bloom 三项一起还原成接管前的值
有 composer、没 Bloom 插入：往编码 pass 前塞一条自己的 TsdPostFXPass，整条链路由它画 pass enabled = false，画面回到宿主原样
没有 composer 内置离屏链路，在原 renderer.render 上做合成 直接转调原函数，零开销

05把改动带出去

面板里调完只是开始，真正的产出是能落回代码的那份东西。

入口产出适合
exportPrompt()
面板底部大按钮		 可直接发给 Agent 的修改提示词：场景概览、目标定位、待应用改动；同一属性多步改动合并成「首次旧值 → 最终值」一行 让 AI 改源码
aiPrompt(targetId?) 指令前言 + 场景概览 + 选中对象全部参数 + 定位代码块 + 待应用改动，写入输出框并自动复制 需要完整上下文的追问
exportCode() 一个对象一段可执行代码：先 const target = scene.getObjectByName("…")，再逐条赋值 直接粘回源码
exportSnapshot() 只含最终被改动的属性、剔除等于基线的项，JSON 文本；loadSnapshot() 返回 {applied, errors} 存档与复现
exportChangeMarkdown() 带说明的改动清单 贴进 issue / PR
后期、环境贴图、helper 开关这类不属于任何 Object3D 的动作，会导出成 tsd.setPostFX(...) / tsd.setEnvironment(...)。默认不写 localStorage，只有显式「保存本地」或 saveSnapshot(name) 才落盘，键统一为 tsd:snapshot:*。

07适合与不适合

它是个开发期 inspector，不是万能渲染平台。

适合

  • 已跑起来的场景要调参、对齐材质与灯光
  • 单页 HTML / 静态 demo 想加面板而不改架构
  • 查掉帧、draw call、三角形数与资源占用
  • 把调参结果交回给源码或 Agent
  • 需要可撤销、可审计的运行时修改

不适合

  • 生产用户遥测、远程调试代理、完整 GPU profiler
  • 从零做 Three 特效、整站 UI 设计、离线模型编辑
  • 覆盖自定义 Shader 全链路（不是着色器 IDE）
  • 未授权就 dispose 你的 GPU 资源或改写 userData
  • 把面板强行打进生产包

08验证与测试

能验证的写清楚，没验证的也写清楚。

terminal
npm test               # 安装器用例，零额外依赖
npm run test:runtime   # 真实 Three 对象上的行为，renderer 为 stub
npm run test:browser   # headless Chrome DOM 断言，关闭 GPU
node scripts/build.cjs # 从核心源重建 dist/ 两种格式

runtime 与 browser 两套用例没有创建真实 WebGLRenderer，因此不能据此声称阴影、纹理上传或画面已通过 GPU 验证。 历史真实 WebGL 验证（SwiftShader 软件光栅化）覆盖核心功能 60/60、导出往返 17/17、跨场景巡检 56/56、自制贴图库 41/41； 软件光栅化能证明「画面确实变了」，但不代表真实 GPU 的性能与驱动兼容性。
